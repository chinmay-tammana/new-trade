## 1. Context & Motivation

In V3.2, the IEX real-time feed failed Gate B (Three-Class Agreement = 72.14% < 75%) and Gate C (GS Missing Minutes = 31.08% > 5%), due to IEX representing only ~2% of total consolidated market volume. Diagnostic audit V3.4 confirmed that this missing volume induced severe **FEED BIAS**:
- Depressed `up_minute_ratio` by -3.46 Base standard deviations.
- Skewed `signed_volume_ratio` (the #1 Down driver in XGBoost) by +1.32 Base standard deviations.
- Artificially suppressed Up signals on recent sessions, producing one-sided Down signals on IEX (7 Down, 0 Up) while consolidated SIP produced balanced two-sided signals (4 Down, 2 Up).

The project owner formally selected **Option B (Delayed SIP for Signals, IEX Display Only)**.

---

## 2. Pre-Registered SIP Gates (Must ALL Pass to Enable Live Signals)

Before `live_signals_enabled` is set to `True`, the delayed SIP pipeline must pass all three objective criteria:

### Gate A: Live Engine Feature Parity on SIP Minutes ($\le 10^{-6}$)
- **Specification**: Features generated by `LiveEngine` using delayed SIP minute bars must equal offline `make_features_v2` on the exact same minutes within a tolerance of $1.0 \times 10^{-6}$ across the last 20 completed sessions (~140 hourly bars).
- **Metric**: $\max_{t, f} |F_{\text{live}}(t, f) - F_{\text{offline}}(t, f)| \le 1.0 \times 10^{-6}$.
- **Purpose**: Guarantees zero implementation drift or feature pipeline divergence in production.

### Gate B: SIP Delayed Access & Lag Compliance for All 8 Symbols
- **Specification**: Alpaca SIP data endpoint must successfully return valid, non-empty minute bars for Goldman Sachs (`GS`) and all 7 context symbols (`SPY`, `XLF`, `JPM`, `MS`, `BAC`, `TLT`, `VIXY`) when query end is at least `alpaca_end_lag_minutes` (15 minutes) old.
- **Metric**: 8 of 8 symbols successfully queried with valid OHLCV minute data without authorization or 403/429 errors.
- **Purpose**: Verifies that the free delayed SIP feed is fully operational without hitting permission walls.

### Gate C: Accelerated Replay Equivalence with `src/predict_day.py`
- **Specification**: Running `LiveEngine` through historical accelerated replay must produce 100% directional agreement and absolute confidence difference $\le 1.0 \times 10^{-9}$ against `src/predict_day.py` on at least 3 distinct trading days:
  1. Full session 1: `2026-11-06` (Replay Benchmark)
  2. Full session 2: `2026-11-05` (Election Volatility Session)
  3. Half-day session: `2024-11-29` (Black Friday 13:00 Early Close)
- **Metric**: Directional match = 100%, Max confidence diff $< 1.0 \times 10^{-9}$ across all bars.
- **Purpose**: Proves that production live inference exactly reproduces the frozen research model.

---

## 3. Operational Policy

- If **all three gates pass**: `live_signals_enabled` is set to `True`. Live signals are computed from delayed SIP (delivered at bar close + 16 min).
- If **any gate fails**: `live_signals_enabled` remains `False`, the live UI displays a prominent warning banner explaining which gate failed, and signals are suppressed.
