# Pre-Registered Protocol: Diagnostic of One-Sided Signals (Nov 10–13, 2026)

**Document Status**: Pre-registered protocol written in Phase 19 (V3.4-DIAG) BEFORE running the diagnostic computations.
**Objective**: Determine why the frozen `model-v2` produced 8 Down, 0 Up, and 16 No-signal bars across the 24 candidate 1-hour candles of November 10–13, 2026, and resolve the contradiction between historical coverage figures (30% pooled OOF, 88.65% V2 holdout, 33% recent sessions).

---

## Pre-Registered Decision Rules (Strict Priority Order)

These four decision rules are evaluated sequentially. The first matching rule determines the verdict and cannot be changed post-hoc.

### Rule 1: Code Bug in Live Engine / Inference Pipeline
- **Condition**: Section A.7 finds any of the following:
  1. Feature values generated by the live engine (`src/live/engine.py`) differ from the canonical offline `make_features` pipeline (`src/features.py`) on the identical bar data by $> 1\times 10^{-6}$ for any feature;
  2. Inverted probability sign or wrong direction assignment mapping in `src/insights.py` or `src/live/server.py`;
  3. Wrong class-weighting or calibrator transform mapping (e.g., using $1 - p$ instead of $p$).
- **Action**: Fix ONLY the live engine and inference code paths. Add an explicit regression test to prevent recurrence. **Leave all trained model artifacts completely untouched**.

### Rule 2: Feed Bias (IEX vs. Consolidated SIP)
- **Condition**: If Rule 1 does not apply, and:
  1. Computing model predictions using consolidated SIP feed features produces mixed (two-sided) directional signals across the 24 candidate candles of Nov 10–13, whereas the IEX feed produces one-sided signals; OR
  2. Swapping a single feature group (volume, intrabar microstructure, peers/VIXY) from IEX values to SIP values restores two-sided signals.
- **Action**: Classify formally as **FEED BIAS**. No model retraining or parameter modification. The dashboard UI will display a prominent "IEX Feed Bias" warning. Present options to the user (e.g., retraining an IEX-specific model vs. utilizing delayed SIP data).

### Rule 3: Trend-Following Macro/Momentum Behaviour (Not a Bug)
- **Condition**: If Rules 1 and 2 do not apply, and either:
  1. Runs of 8 consecutive directional signals being strictly one-sided occur in $\ge 5.0\%$ of all rolling windows of 8 consecutive directional signals in historical pre-holdout OOF or Research Holdout predictions; OR
  2. The Spearman rank correlation $|\rho| \ge 0.30$ between calibrated probability $p_{\text{cal}}$ and trailing returns (`ret_5d` or `ret_20d`) over the last 250 trading sessions on SIP features.
- **Action**: Classify formally as **TREND-FOLLOWING BEHAVIOUR, NOT A BUG**. No code or model changes. Retain all thresholds and display truthful telemetry and diagnostic context on the dashboard.

### Rule 4: Inconclusive
- **Condition**: If none of Rules 1, 2, or 3 are satisfied.
- **Action**: Classify formally as **INCONCLUSIVE, SMALL SAMPLE**. No changes to code, models, or thresholds.

## Mandatory Constraints
1. **Model Lock**: `model-v2` is strictly FROZEN. Hashes of `models/model_v2.joblib`, `models/calib_v2.joblib`, and `models/calib_live.json` must remain identical to `models/MODEL_SHA256.json`.
2. **Ledger Immutability**: No rows in the `signals` table in `data/live/live.db` may be modified or deleted.
3. **No Artificial Balancing**: No shifting of $q_{\text{lo}}$ or $q_{\text{hi}}$, no quotas, no mirroring.
4. **Data-Driven Reporting**: Every number presented in the dashboard, documentation, and reports must originate from a computed CSV in `results/tables/`.
