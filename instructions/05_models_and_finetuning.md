# Phase 5: Models, Training, and Fine-Tuning

======================================================================
PHASE 5: MODELS, TRAINING AND FINE-TUNING (src/models.py, src/train_base.py, src/finetune.py) (IMPACT Steps 7-8)
======================================================================
STAGE A: base training. Fit default-ish XGBClassifier (max_depth=3, learning_rate=0.05, n_estimators=200, subsample 0.8, colsample_bytree 0.8, eval_metric logloss, random_state 42, n_jobs 1) on Base decisive rows. Sanity: TimeSeriesSplit(n_splits=5, gap=8) CV inside Base; report train vs CV log-loss. Score on Val: log-loss, Brier, accuracy = strategy S0 ("before fine-tuning"). Save models/base_model.json.
STAGE B, PART A: walk-forward hyperparameter search over the FT block (used identically for every candidate model below).
- Split FT labelled rows into ft_cv_folds (4) chronological chunks C1..C4. Fold k: train = Base decisive rows (weight base_weight) + decisive rows of chunks before k, excluding rows within gap_bars bars before chunk k's first bar; validate on ALL labelled rows of chunk k; metric log-loss.
- XGBoost: sample n_iter_search (40) configurations with sklearn ParameterSampler (seed 42), including base_weight. Log every configuration and fold score to experiment_log.csv and results/tables/cv_results.csv. Configurations within 0.001 mean log-loss are ties; prefer the simpler (shallower, fewer trees).
STAGE B, PART B: XGBoost fine-tuning strategies, compared on Val (all labelled rows) by log-loss, Brier, accuracy:
- S0: base model. S1: Base only with tuned params. S2: refit from scratch on Base (weight base_weight) + the whole FT block. S3: warm start: train on Base with tuned params, then continue boosting on the FT block via fit(..., xgb_model=<base booster>) with rounds and learning rate chosen from the config options (small search selected on Val).
- Pick the lowest Val log-loss; ties go to the simpler (S1 < S2 < S3). Never refit on Val or Test.
STAGE C: conventional ML comparators (explain in docs/model_choice.md why each is included): logistic regression (interpretable linear benchmark; tune C), Random Forest (non-linear bagging benchmark; small grid over n_estimators, max_depth, min_samples_leaf), sklearn HistGradientBoostingClassifier (second boosting benchmark; small grid over learning_rate, max_depth, max_iter). Each is tuned with the SAME Part A walk-forward folds, refit on Base + FT (strategy S2), and later passed through the same calibration and signal-rule procedure. Record training time, inference time and model size for every model.
STAGE D: ablations for XGBoost (same procedure, seed 42, selected on Val log-loss, keep the list short): with/without time features; with/without SPY and XLF; with/without rvol; with/without class-balanced weights; label threshold candidates; optional alpaca_feed=iex versus sip. Record what did not help.
STAGE E: feature importance: gain and permutation importance on Val; drop a feature only if Val agrees.
Final model selection: the deployed model is the best XGBoost strategy from Part B, UNLESS a comparator from Stage C beats it on Val log-loss by more than switch_margin_logloss, in which case deploy that comparator, record the decision in progress.md and update the title and docs accordingly. Save the final model as models/model.joblib (and models/model.json for XGBoost); save every candidate under models/candidates/. Log fits in the ledger. Write results/tables/finetune_report.md (S0-S3 table, comparator table, ablations, what did not work).
CHECK: cv_results.csv and experiment_log.csv exist; strategy and comparator tables exist; overfit check done (train vs CV vs Val log-loss); the ledger proves no Val/Test row was used in any fit.
